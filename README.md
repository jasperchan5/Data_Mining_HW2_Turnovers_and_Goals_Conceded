# 哪些傳球失誤會直接導致失球？
### 用 Wyscout 事件資料偵測「致命的丟失球權」

> NYCU Data Mining HW2（Anomaly Detection）
> 狀態：**主實驗、消融、誤差分析完成**（2026-11-05，落點補值修正第二版）。所有結果可以用 `bash run_all.sh` 在一般電腦上約 10–20 分鐘重現
> 資料類別：**Tabular**（作業 5 類中的第 2 類），一筆資料 = 一次傳球失誤
> 姊妹專案：`hw2_foul_card`（犯規 → 吃牌）。兩者用同一份原始資料、同一種切分與評估協定

---

## 一句話說明

只用「傳球失誤當下就知道的資訊」（在哪裡丟、球落在哪裡、是否回傳、是否在對手壓迫下），判斷**這次失誤會不會在 15 秒內導致失球**。只用「沒有導致失球的失誤」訓練的 Isolation Forest 顯著優於隨機，和最好的單一特徵（球的落點）在 PR-AUC 上打平；把分數改成只看「往危險方向的罕見」（單邊尾端）後，PR-AUC 顯著提高 70%，點估計超過單一特徵。監督式 XGBoost 仍然最好，但所有方法的絕對表現都很低：很多致命失誤要經過好幾次傳遞才失球，從失誤當下看不出來。

## 1. 為什麼做這題

| 項目 | 內容 |
|---|---|
| **使用者** | 球隊的影片分析師、教練 |
| **決策** | 一場比賽約 146 次傳球失誤，平均只有約 0.45 次直接導致失球。賽後檢討時先看哪幾次？ |
| **警示之後的動作** | 把失誤排進檢討片段，找出「在哪種情況下出錯最致命」，用於訓練 |
| **審查預算** | 前 1% 與前 10% 的失誤（§5.4） |

**研究問題：**
> 只用「沒有造成失球的失誤」學出正常樣貌，能不能把致命的失誤當成異常抓出來？和犯規題目相比，結果有什麼不同？

**異常的定義（看結果之前就固定）：** 一次不準確的傳球（`Pass` 且帶 tag 1802），之後 15 秒內、同一個半場，對手進球（射門或自由球帶 tag 101，或我方烏龍球 tag 102）。

| | 例子（定義上的樣貌） |
|---|---|
| **正常** | 在對方禁區前傳中，被後衛解圍，對手往前推進，但沒有進球 |
| **異常** | 在自家禁區前被逼著回傳出錯，對手搶到球後 15 秒內進球 |

## 2. 資料

**Wyscout 公開事件資料**（Pappalardo et al. 2019，figshare），和犯規題目相同：

| 檔案 | 內容 | 用途 |
|---|---|---|
| `events_*.zip` | 3,251,294 個事件 | 傳球失誤、進球、前 10 秒情境 |
| `matches_*.json` | 1,941 場的日期、主客場 | 切分、主客場 |
| `players.json` | 3,603 名球員的位置 | 傳球者角色 |

- 賽事：英、法、德、義、西 2017/18 頂級聯賽，2016 歐洲盃，2018 世界盃
- 期間：2016-06-10 到 2018-07-15

### 2.1 一筆資料與標籤

| 項目 | 定義 |
|---|---|
| **一筆資料** | 一次 `Pass` 且帶 tag 1802（不準確）的事件，共 284,019 次 |
| **標籤** | 之後 15 秒內、同一個半場，對手進球 → 1 |
| **預測時間點** | 傳球的當下 |
| **不算丟球權** | 對抗（`Duel`）失敗。Wyscout 的對抗兩邊各記一筆，防守方被過掉也會記成「對抗失敗」，那不是丟球權 |
| **不能用** | 傳球之後的任何事件（落點補值是唯一例外，見 §2.3）；tag 2001（`dangerous_ball_lost`），標註員可能看完後續才標 |

**15 秒這個時間窗的影響**（探索階段的計數，包含對抗失敗，僅供參考）：10 秒 3,958 次、15 秒 4,976 次、30 秒 7,013 次。只算傳球失誤時，15 秒內有 869 次。

**tag 2001 不適合當標籤**：資料中有 4,028 次事件帶「危險的丟失球權」tag；其中同時是傳球失誤或對抗失敗、而且之後 15 秒內失球的，只有 299 次（其他事件類型沒有檢查）。標註員認為「危險」的丟球，大多沒有導致失球。

### 2.2 類別不平衡

| 切分 | 場次 | 失誤 | 15 秒內失球 | 比例 |
|---|---|---|---|---|
| 訓練 | 1,164 | 170,396 | 501 | 0.29% |
| 驗證 | 388 | 59,351 | 186 | 0.31% |
| 測試 | 389 | 54,272 | **182** | **0.34%** |
| 合計 | 1,941 | 284,019 | 869 | 0.31%（約 1 : 330） |

不平衡程度和信用卡詐騙相當。「全部判正常」的 accuracy 是 99.66%，所以 accuracy 不能當指標。

5,223 個進球中，有 812 個在進球前 15 秒內有對手的傳球失誤；869 次失誤對應這 812 個進球（少數進球前有多次失誤）。

### 2.3 落點缺值的修正

**問題：** 8,380 次失誤（3.0%）的傳球落點記為 **(0, 0)**，也就是剛好在我方球門線的角落。檢查原始事件後發現這是 Wyscout 沒有記錄落點時的佔位值：

| 檢查項目（世界盃 + 英超，2,016 次落點 x = 0） | 結果 |
|---|---|
| 落點剛好是 (0, 0) | 97% |
| 傳球種類 | 85% 是傳中 |
| 傳球起點 | 中位數 x = 89，91% 在對方半場 |
| 下一個事件 | 96% 是對手，多半是對手在他們自己的禁區觸球（例如 x = 4–13）或守門員出擊 |

也就是說，這些多半是**在對方禁區前傳中失敗**，球被解圍或被守門員接走，而不是傳到自家底線。

**修正（`fix_end`）：** 落點為 (0, 0) 時，用**之後第一個有真實座標的事件**補回（同一個半場、相隔不超過 5 秒）：
- 跳過沒有座標的事件、比賽中斷（`Interruption`），以及座標是**四個角落佔位值**（x、y 都是 0 或 100）的事件
- 找到的事件是對手的：座標換回我方視角 (100 − x, 100 − y)，共 6,164 次
- 找到的事件是本隊的：直接用，共 278 次
- 找不到：用傳球起點代替，共 1,938 次

補值後的落點 x 中位數是 91，符合「在對方禁區前丟球」。七個賽事都有這個問題（每個聯賽約 1,150–1,750 次），修正規則一致套用。

**第二版修正（誤差分析發現的）：** 第一版只看「下一個事件」。但傳中被守門員接走時，下一個事件常是「守門員出擊」或「撲救」，Wyscout 把它們的座標記成角落佔位值 (100, 100)；換回我方視角後落點又變成 (0, 0) 附近，等於把傳中又放回自家底線。英超裡，(0, 0) 傳中的下一個對手事件有 337 次是「守門員出擊」、41 次是「撲救」，座標全是角落。誤差分析（§6.4）時發現：單一特徵的測試集前 1% 裡有 341 次在對方三分之一丟球，其中 334 次就是這種補錯的傳中，全部沒有失球。第二版改成跳過佔位座標往後找，影響 1,847 次失誤（標籤不變）。

**例外說明：** 補值用到了傳球之後的事件，但只取它的**位置**來補回「這次傳球本身的落點」，這個資訊原本就屬於傳球事件，只是沒被記錄。其他特徵都不使用之後的事件。

**影響：** 補值的失誤失球率只有 0.05%（全體 0.31%）。沒有修正時，它們被當成「球掉到自家球門前」，排在單一特徵的最前面；`end_x`、`end_lateral`、`pass_len`、`backward` 都受到影響（三個版本的比較見 §6.1）。

## 3. 特徵（28 個）

全部只用傳球當下或之前的資訊。比分、本隊累計失誤數都在記錄後才更新。

| 組 | 特徵 | 意思 |
|---|---|---|
| **原始（19 個）** | `x`、`lateral` | 丟球位置；x = 0 是自家球門，`lateral` = \|y − 50\| |
| | `end_x`、`end_lateral`、`pass_len` | 球落在哪裡、傳球長度（公尺，以 105 × 68 換算）；落點已修正（§2.3） |
| | `backward` | 落點比起點更靠近自家球門 |
| | `pt_*`（7 個） | 傳球種類：一般、高球、大腳、傳中、頭球、穿透、手拋 |
| | `minute`、`home` | 比賽分鐘、是否主場 |
| | `role_DF/MD/FW/GK` | 傳球者位置 |
| **情境（9 個）** | `dist_own_goal`、`in_own_third` | 丟球點到自家球門距離、是否在自家三分之一 |
| | `counter_attack` | 這次傳球帶有反擊 tag |
| | `score_diff`、`team_prev_losses` | 當下比分差、本隊本場之前失誤幾次 |
| | `own_events_10s`、`opp_events_10s` | 前 10 秒兩隊的動作數 |
| | `opp_duel_3s` | 前 3 秒內對手有對抗（壓迫的近似） |
| | `own_min_x_10s` | 本隊前 10 秒最靠近自家球門的位置 |

**危險特徵組（6 個，事先依足球常識定義，不看標籤）：** `dist_own_goal`、`lateral`、`end_x`、`end_lateral`、`backward`、`opp_duel_3s`。也就是在哪裡丟、球丟到哪裡、是不是回傳、是否在壓迫下。

## 4. 探索分析（只用訓練場次）

**依丟球位置：**

| 區域 | 失誤數 | 佔全部失誤 | 15 秒內失球率 |
|---|---|---|---|
| 自家三分之一 | 48,526 | 28.5% | **0.54%** |
| 中場三分之一 | 63,658 | 37.4% | 0.27% |
| 對方三分之一 | 58,212 | 34.2% | 0.11% |

自家三分之一的失誤，失球率是對方三分之一的 4.8 倍；但它佔了 28.5%，一點都不罕見。

**單一特徵可分性**（訓練集）：

| 特徵 | 方向化 AUC | KS | 致命失誤平均 | 一般失誤平均 |
|---|---|---|---|---|
| `end_x` | 0.769 | 0.402 | 43.9 | 66.9 |
| `dist_own_goal` | 0.679 | 0.261 | 43.8 | 59.5 |
| `x` | 0.670 | 0.253 | 37.5 | 52.3 |
| `own_min_x_10s` | 0.622 | 0.205 | 30.9 | 39.8 |
| `in_own_third` | 0.618 | 0.237 | 52.1% | 28.4% |
| `pass_len` | 0.610 | 0.202 | 17.4 | 24.1 |
| `pt_simple_pass` | 0.607 | 0.214 | 59.9% | 38.4% |
| `score_diff` | 0.605 | 0.189 | −0.49 | −0.04 |

- **球落在哪裡比在哪裡丟更重要**：`end_x` 的 AUC 0.769，最高（修正落點前是 0.747）。
- **致命失誤的傳球比較短**（17.4 對 24.1 公尺），多是一般短傳（59.9% 對 38.4%），符合「在自家半場被逼著短傳出錯」。
- **回傳的失球率是其他方向的兩倍多**（0.54% 對 0.25%）。

圖 `results/figures/fig1_eda_train.png`：訓練集中正常與致命失誤的 `end_x`、`dist_own_goal` 分布，以及回傳與否的失球率。

**探索階段的假設**（在 §6 檢驗）：
- **H1**：致命失誤集中在「球往自家球門方向掉」的一側（落點低、回傳）。
- **H2**：危險只在單一方向：在對方禁區前丟球雖然也可能罕見，但不危險。所以只看罕見度、不分方向的雙邊分數會被安全方向的罕見值干擾。
- **H3**：失誤當下的資訊只能解釋一小部分；要等之後好幾次傳遞才進球的失誤，從當下很難看出來。
- **落後時比較容易失誤後失球**（平均比分差 −0.49），可能是落後的球隊壓上、身後空檔較大。

## 5. 方法與實驗設計

### 5.1 三層方法

| 層 | 方法 | 用到的標籤 |
|---|---|---|
| **Tier 1** | (a) 全部判正常；(b) 隨機分數；(c) 單一特徵：訓練集方向化 AUC 最高的 `end_x`（越小分數越高） | (c) 只用訓練集選特徵 |
| **Tier 2** | Isolation Forest，只用訓練集**沒有導致失球**的失誤（169,895 次）訓練；`StandardScaler` 也只在這些資料上 fit。分數 s(x) = −`score_samples`(x)，越大越異常 | 訓練：不用；特徵組、超參數、τ：驗證集 |
| **Tier 2 參考** | Mahalanobis 距離（危險特徵組） | 同上 |
| **Tier 2 消融** | 單邊尾端 Isolation Forest：標準化後乘上事先決定的危險方向，安全方向的偏離壓成 0（§6.3 A2） | 同上；方向不用標籤 |
| **Tier 3** | XGBoost 監督式分類，28 個特徵 | 訓練集標籤 |

### 5.2 切分與防止洩漏

| 項目 | 設定 |
|---|---|
| **切分** | 依比賽日期排序：前 60% 場次訓練（到 2018-02-03）、接著 20% 驗證（到 2018-04-07）、最後 20% 測試。和犯規題目完全相同的場次切分 |
| **三層共用** | 同一份切分、同一組指標、同一批測試失誤 |
| **驗證集** | 只用來選特徵組、超參數和 τ |
| **測試集** | 最後只評估一次 |
| **落點補值** | 規則固定（§2.3），所有切分一致套用，不用標籤 |

### 5.3 超參數（只用驗證集 PR-AUC 選）

| 方法 | 搜尋範圍 | 選出 |
|---|---|---|
| Isolation Forest | 特徵組 {全部 28 個, 危險 6 個} × 樹數 {200, 500} × ψ {256, 1024, 4096} × max_features {0.5, 1.0} | **危險 6 個**、500 棵、ψ = 256、max_features = 0.5（驗證 PR-AUC 0.0076；全部 28 個特徵的最佳組只有 0.0053） |
| XGBoost | max_depth {3, 5} × min_child_weight {1, 10}；learning rate 0.05，早停 100 輪 | depth 3、min_child_weight 10、153 棵樹（驗證 PR-AUC ⟨待補⟩） |

### 5.4 指標

| 指標 | 為什麼 |
|---|---|
| **PR-AUC**（主指標） | 隨機猜的基準是異常比例（測試集 0.0034） |
| **前 1% / 前 10% 抓到幾次** | 對應「檢討時只看 1% 或 10% 的失誤」；測試集的 1% 是 543 次、10% 是 5,427 次 |
| ROC-AUC | 輔助 |

每個方法 5 個 seed（0–4），報告平均 ± 標準差。

**顯著性：**
- 差距用**以比賽為單位的 block bootstrap**（1,000 次）算 95% CI，比較的是 5 個 seed **平均後的分數**。
- 平均後的分數比單一 seed 穩定，所以 bootstrap 表中的點估計，會和主表「5 個 seed 各自 PR-AUC 的平均」不同（§6.1 有說明）。
- Tier 2 和 Tier 3 另做 5 個 seed 的配對 t 檢定。

## 6. 結果

### 6.0 各層實際用到的樣本數

三層從**同一份原始切分**出發（依比賽日期：1,164 / 388 / 389 場），在**同一個驗證集**上調參數與 τ、在**同一個測試集**上評估。差別只在訓練時用了哪些訓練樣本：

| 層 | 方法 | 訓練：正常 | 訓練：異常（致命） | 說明 |
|---|---|---|---|---|
| Tier 1 | 全部判正常、隨機分數 | 0 | 0 | 不需要訓練 |
| Tier 1 | 單一特徵（`end_x`） | 169,895 | 501 | 只用訓練集的標籤挑特徵與方向，沒有學參數 |
| Tier 2 | Isolation Forest（全部 28 個 / 危險 6 個） | 169,895 | **0** | Normal-only：從訓練切分濾掉所有致命失誤；`StandardScaler` 也只在這些資料上 fit |
| Tier 2 參考 | Mahalanobis（危險 6 個） | 169,895 | **0** | 同上 |
| Tier 3 | XGBoost | 169,895 | 501 | 監督式，保留同一份訓練切分裡的異常樣本 |
| — | 驗證集（選特徵組、超參數、早停、τ） | 59,165 | 186 | 所有方法共用 |
| — | 測試集（只評估一次） | 54,090 | 182 | 所有方法共用 |

### 6.1 主要結果（測試集 54,272 次失誤、182 次致命）

| 方法 | PR-AUC | ROC-AUC | 前 1% 抓到 | 前 10% 抓到 | F1（τ：驗證集最佳 F1） | 訓練（秒） | 推論（ms / 筆） |
|---|---|---|---|---|---|---|---|
| T1 全部判正常 | 0.0034 | 0.500 | 0 | 11 | 0 | — | — |
| T1 隨機 | 0.0036 ± 0.0002 | 0.506 ± 0.012 | 3.0 ± 1.4 | 18.8 ± 2.5 | 0.005 ± 0.003 | — | — |
| T1 單一特徵（`end_x`） | 0.0121 | 0.770 | 11 | 73 | 0.043 | — | — |
| T2 Isolation Forest，全部 28 個特徵 | 0.0045 ± 0.0003 | 0.571 ± 0.012 | 2.6 ± 1.0 | 29.6 ± 4.1 | 0.005 ± 0.006 | 1.31 | 0.016 |
| **T2 Isolation Forest，危險 6 個（驗證集選出）** | **0.0102 ± 0.0005** | 0.617 ± 0.005 | 8.6 ± 0.5 | 49.2 ± 1.3 | 0.025 ± 0.003 | 1.25 | 0.021 |
| T2 參考：Mahalanobis，危險 6 個 | 0.0057 | 0.595 | 4 | 39 | 0.017 | — | — |
| T3 XGBoost | **0.0302 ± 0.0007** | **0.828 ± ⟨待補⟩** | **29.8 ± ⟨待補⟩** | **93.0 ± ⟨待補⟩** | **0.078 ± ⟨待補⟩** | 1.64 | 0.001 |

「全部判正常」的分數全部相同，前 1% / 10% 是依原始順序取，只是參考值。

**跨平台重現**：本表與 `results/` 是在 Windows（Git Bash、Python 3.12.10）上執行 `run_all.sh` 的結果。Tier 1–2、所有 Isolation Forest 消融與誤差分析的 TP / FP / FN 在 Windows 與 Linux 上逐位元相同；XGBoost（`tree_method=hist`）因浮點運算與多執行緒加總順序不同，在不同平台上會略有差異（Linux：早停選出 128 棵樹、測試 PR-AUC 0.0297 ± 0.0011、前 1% 30.2），但所有排名與結論都不變。

**PR-AUC 差距**（以比賽為單位的 block bootstrap 95% CI，5 個 seed 平均後的分數）：

| 比較 | 差距 | 95% CI | 結論 |
|---|---|---|---|
| T2 − 隨機 | +0.0061 | [+0.0011, +0.0183] | 顯著 |
| T2 − 單一特徵 | −0.0022 | [−0.0061, +0.0091] | **打平** |
| T3 − T2 | +0.0206 | [+0.0082, +0.0343] | T3 顯著比較好（5 seed 配對 t 檢定 p = 8.9 × 10⁻⁷） |
| T3 − 單一特徵 | +0.0184 | [+0.0105, +0.0322] | T3 顯著比較好 |
| T2 危險 6 個 − T2 全部 28 個 | +0.0054 | [+0.0020, +0.0177] | 挑特徵顯著有幫助 |

**怎麼解讀：**
- **Tier 2 和 Tier 1 打平**：PR-AUC 的點估計 T2 略低（0.0102 對 0.0121），但 CI 包含 0。前 1% 兩者接近（8.6 對 11），前 10% 和 ROC-AUC 是單一特徵明顯較好（73 對 49.2；0.770 對 0.617）。
- **但兩者用的資訊不同**：單一特徵是用訓練集**標籤**挑出 `end_x` 和方向；T2 完全沒看過致命失誤。
- **挑特徵是必要的**：用全部 28 個特徵時，Isolation Forest 只比隨機稍好（0.0045）。
- **絕對表現都很低**：最好的 XGBoost，看前 1%（543 次）也只抓到約 30 次。
- **為什麼 T2 沒有贏**：雙邊的 Isolation Forest 把「往安全方向罕見」的失誤也算成異常（§6.3 A2、§6.4 驗證這點）。

**落點修正三個版本的比較**（舊版本已覆蓋，數字取自當時的執行紀錄，都是 Linux）：

| 方法 | PR-AUC：未修正 → 第一版 → 第二版 | 前 1%：未修正 → 第一版 → 第二版 | 前 10%：未修正 → 第一版 → 第二版 |
|---|---|---|---|
| T1 單一特徵 | 0.0080 → 0.0102 → **0.0121** | 0 → 3 → **11** | 59 → 72 → 73 |
| T2 危險 6 個 | 0.0095 → 0.0093 → 0.0102 | 9.6 → 7.8 → 8.6 | 47.6 → 47.4 → 49.2 |
| T3 XGBoost（Linux） | 0.0323 → 0.0315 → 0.0297 | 31.2 → 29.6 → 30.2 | 94.4 → 93.8 → 93.2 |

修正主要幫到單一特徵：補錯的傳中（落點 x ≈ 0）會被排在 `end_x` 的最前面，但幾乎都不致命。T2、T3 會同時看其他特徵，受影響較小。T2 第二版的超參數也改變了（見 §5.3）。

### 6.2 Isolation Forest 標記了什麼（測試集，分數前 1%）

| 平均值 | 標記、致命 | 標記、沒失球 | 沒標記、致命 | 沒標記、沒失球 |
|---|---|---|---|---|
| 丟球位置 x | **18.1** | 30.2 | 39.7 | 53.1 |
| 落點 x | **9.0** | 24.4 | 44.8 | 67.6 |
| 回傳 | **100%** | 84.8% | 30.1% | 15.9% |
| 對手 3 秒內有對抗 | 22.2% | **71.2%** | 20.8% | 20.1% |
| 傳球長度（公尺） | 17.2 | 15.0 | 16.3 | 23.9 |

- **方向是對的**：被標記的失誤幾乎都是「球往自家球門方向掉」的回傳（支持 H1）。
- **被標記但沒失球的失誤，71% 在對手壓迫下**：Isolation Forest 把「在壓迫下」這個少見的狀態也當成異常，但致命失誤裡有壓迫的比例（22%）和一般失誤（20%）差不多，見 §6.3 A3「− 壓迫」。
- **和犯規題目的關鍵差別**：在這裡，罕見的方向（回傳到自家球門附近）大致就是危險的方向。犯規題目裡，罕見的方向（手球、已有黃牌）卻是比較不會吃牌的方向。

### 6.3 消融（Tier 2，一次只改一個因素，5 個 seed）

其他設定都和主方法相同：危險 6 個特徵、驗證集選出的超參數、只用正常樣本訓練、τ 取驗證集最佳 F1。表中「驗證」是驗證集 PR-AUC，「測試」是測試集。結果在 `results/ablations.csv`，圖在 `results/figures/fig3_ablations.png`。

**A1 訓練資料污染**（normal-only 的必要性）

| 訓練資料混入致命失誤 | 驗證 PR-AUC | 測試 PR-AUC | 前 1% | 前 10% |
|---|---|---|---|---|
| **0%（只用正常樣本，主方法）** | 0.0075 | 0.0102 ± 0.0005 | 8.6 | 49.2 |
| 0.1% | 0.0074 | 0.0101 ± 0.0004 | 8.6 | 49.4 |
| 0.2% | 0.0074 | 0.0101 ± 0.0005 | 8.4 | 49.4 |
| 0.29%（全部 501 次，等於不過濾） | 0.0074 | 0.0107 ± 0.0012 | 9.0 | 49.6 |

污染幾乎沒有影響。原因是致命失誤本身只佔 0.29%：即使全部放進訓練，Isolation Forest 每棵樹只抽 256 筆，平均不到 1 筆是致命失誤，不足以改變「正常」的樣貌。所以在這題，normal-only 是協定上的要求，不是效果的來源。

**A2 分數函數（異常偵測特有的消融）**

| 分數 | 驗證 PR-AUC | 測試 PR-AUC | ROC-AUC | 前 1% | 前 10% |
|---|---|---|---|---|---|
| **Isolation Forest，雙邊（主方法）** | 0.0075 | 0.0102 ± 0.0005 | 0.617 | 8.6 | 49.2 |
| **Isolation Forest，單邊尾端** | **0.0128** | **0.0173 ± 0.0012** | **0.733** | **16.6** | **68.0** |
| 單邊偏離量直接加總（不用模型） | 0.0118 | 0.0125 | 0.710 | 13 | 62 |
| Mahalanobis 距離 | 0.0052 | 0.0057 | 0.595 | 4 | 39 |
| kNN 平均距離（k = 10） | 0.0065 | 0.0074 ± 0.0004 | 0.616 | 8.4 | 49.0 |
| GMM 負對數概似（8 群） | 0.0059 | 0.0069 ± 0.0010 | 0.605 | 8.2 | 45.8 |

**單邊尾端**：標準化之後，把每個危險特徵乘上事先決定的方向（`DANGER_SIGN`，例如 `end_x` 越小越危險、回傳越危險），再把負值（安全方向的偏離）壓成 0，然後才給 Isolation Forest。這樣只有往危險方向罕見的失誤會被隔離出來。方向是依足球常識事先決定的，沒有用標籤，仍然只用正常樣本訓練。

| 比較（5 個 seed 平均後的分數） | 差距 | 95% CI | 結論 |
|---|---|---|---|
| 單邊 − 雙邊 | +0.0087 | [+0.0032, +0.0137] | **單邊顯著比較好** |
| 單邊 − 單一特徵 | +0.0065 | [−0.0012, +0.0207] | 點估計較好，但 CI 包含 0 |
| XGBoost − 單邊 | +0.0119 | [−0.0019, +0.0275] | CI 包含 0 |
| 加總 − 單邊 Isolation Forest | −0.0061 | [−0.0121, −0.0011] | Isolation Forest 顯著比直接加總好 |

- **支持 H2**：同樣的特徵、同樣只用正常樣本，只改成單邊，測試 PR-AUC 從 0.0102 升到 0.0173，前 1% 抓到的次數幾乎翻倍（8.6 → 16.6），**在驗證集上也一樣比較好**（0.0128 對 0.0075，也高於單一特徵的 0.0114）。也就是說，如果一開始就把單邊放進驗證集的選擇範圍，選出來的會是它。
- **單邊 Isolation Forest 在每個指標的點估計都超過單一特徵**（PR-AUC 0.0173 對 0.0121、前 1% 16.6 對 11），但 PR-AUC 差距的 CI 包含 0，只能說「傾向較好」。
- **Isolation Forest 本身有貢獻**：直接把單邊偏離量加總（不用模型）顯著比較差，表示特徵之間的組合（例如「在自家半場」且「回傳」）有用。
- **其他雙邊分數都比 Isolation Forest 差**：Mahalanobis、kNN、GMM 都假設「離中心遠就是異常」，同樣會被安全方向的罕見值干擾。

**A3 特徵組**

| 特徵組 | 驗證 PR-AUC | 測試 PR-AUC | 前 1% | 前 10% |
|---|---|---|---|---|
| **危險 6 個（主方法）** | 0.0075 | 0.0102 ± 0.0005 | 8.6 | 49.2 |
| 全部 28 個 | 0.0044 | 0.0044 ± 0.0002 | 3.2 | 25.6 |
| − 丟球位置（`dist_own_goal`、`lateral`） | 0.0074 | 0.0107 ± 0.0001 | 13.2 | 50.6 |
| − 落點（`end_x`、`end_lateral`） | 0.0046 | 0.0055 ± 0.0001 | 3.0 | 35.4 |
| − 回傳（`backward`） | 0.0059 | 0.0065 ± 0.0003 | 7.4 | 39.4 |
| − 壓迫（`opp_duel_3s`） | 0.0085 | 0.0110 ± 0.0005 | 13.6 | 53.6 |
| + 情境 5 個（反擊、比分差、前 10 秒動作數、本隊最後防線） | 0.0059 | 0.0062 ± 0.0001 | 6.0 | 39.2 |
| 參考：XGBoost 只用危險 6 個（監督式） | 0.0283 | 0.0261 ± 0.0004 | 25.4 | 84.6 |

- **落點最重要**，拿掉後幾乎掉到全部 28 個的水準；回傳次之。
- **拿掉壓迫反而比較好**（驗證、測試都是）：壓迫本身不少見（約 20%），但和其他特徵組合後會產生「罕見但不危險」的組合，正好是 §6.2 那 71% 的誤報。
- **加入情境特徵變差**：更多維度讓「罕見」被稀釋到和失球無關的方向（例如比分差很大）。
- **標籤比特徵重要**：XGBoost 只用同樣 6 個特徵就有 0.0261，接近用全部 28 個的 0.0302。T2 和 T3 的差距主要來自「有沒有用標籤」，不是特徵。

**A4 門檻 τ**（同一組分數，只改 τ；PR-AUC 不受影響）

| τ 的決定方式 | 測試警示比例 | Precision | Recall | F1 |
|---|---|---|---|---|
| **驗證集最佳 F1（主方法）** | 1.40% | 1.58% | 6.4% | 0.025 |
| 審查預算 1%（驗證集分數的 99 百分位） | 1.07% | 1.55% | 5.0% | 0.024 |
| 審查預算 10%（驗證集分數的 90 百分位） | 10.27% | 0.90% | 27.6% | 0.018 |
| 不用標籤：正常訓練分數的 99 百分位 | 1.03% | 1.58% | 4.8% | 0.024 |

- **不用任何標籤的 τ，F1 和用驗證集標籤選的幾乎一樣**（0.024 對 0.025）。實際使用時可以不需要標註好的驗證集。
- 審查預算從 1% 放寬到 10%，recall 從 5% 升到 28%，precision 從 1.6% 降到 0.9%（仍是隨機 0.34% 的 2.6 倍）。

測試集標記 593 次（1.09%）：**TP 10、FP 583、FN 172**。單邊版本同樣預算下是 TP 18、FP 564。

**四種結果的平均樣貌**（`results/error_outcome_profile.csv`；最後三列是失誤**之後**發生的事，只用於解釋，不是特徵）：

| 平均值 | TP | FP | FN | TN |
|---|---|---|---|---|
| 次數 | 10 | 583 | 172 | 53,507 |
| 丟球位置 x | 18.8 | 31.2 | 39.7 | 53.1 |
| 落點 x | 9.5 | 25.4 | 44.9 | 67.6 |
| 回傳 | 100% | 84.6% | 29.7% | 15.8% |
| 對手 3 秒內有對抗 | 30% | 70.5% | 20.3% | 20.1% |
| 對手 15 秒內射門 | 100% | **12.2%** | 98.8% | **2.2%** |

- **FP 多半是「危險但沒進」**：被標記但沒失球的失誤，12.2% 在 15 秒內讓對手射門，是未標記失誤（2.2%）的 5.6 倍。這些 FP 從比賽來看是真的危險，只是對手沒有射進。15 秒內失球的標籤比「危險」嚴格得多，所以 precision 天生偏低。
- **FN 多半是「之後才發生的事」**：抓到的致命失誤，平均 3.2 秒、2 個事件後就失球，幾乎是直接送球；漏掉的致命失誤平均要 9.5 秒、5.7 個事件，丟球位置在中場附近（x = 39.7），中間還經過對手好幾次傳遞。這種失誤的危險來自之後的攻防，失誤當下的資訊看不出來（支持 H3）。
- **依丟球位置**（`results/zone_breakdown_top1.csv`，前 1%）：所有方法抓到的致命失誤幾乎都在**自家三分之一**（單一特徵 11/11、T2 9/9、單邊 15/17、T3 25/29）。中場的 65 次致命失誤、對方三分之一的 28 次，沒有任何方法在前 1% 抓到超過 4 次。T2 雙邊在對方三分之一標記了 86 次（0 次命中），單邊只標記 2 次：這就是雙邊被安全方向罕見值干擾的直接證據。

**具體案例**（`results/error_cases.csv`；分數百分位是在測試集中的排名，越接近 1 越異常）：

| 案例 | 比賽（Wyscout matchId / eventId） | 失誤 | T2 百分位 | 之後發生什麼 | 主要原因（遮蔽法貢獻） |
|---|---|---|---|---|---|
| **TP**：分數最高的致命失誤 | RB Leipzig − Bayer Leverkusen 1−4，第 51 分鐘（2516992 / 241541412） | Leipzig 的 W. Orban 在自家禁區前（x = 24）被壓迫下回傳，球落在 x = 12、正中路 | 1.000 | 1.8 秒後失球，中間只有 1 個事件 | 回傳、正中路、落點低，六個特徵都往危險方向 |
| **FP**：分數最高的非致命失誤 | Schalke 04 − Eintracht Frankfurt 1−0，第 67 分鐘（2517040 / 251299395） | Frankfurt 的 M. Russ 在自家禁區（x = 18）被壓迫下 33 公尺回傳，落點 x = 9、**靠近邊線**（`end_lateral` = 47） | 1.000 | 沒有射門 | 回傳、正中路丟球、落點低；XGBoost 因落點在邊線而給低分（`end_lateral` SHAP −1.31） |

- **FP（Frankfurt）說明了雙邊與「邊線」的問題**：落點靠近邊線（`end_lateral` = 47）在一般失誤中很罕見，所以 Isolation Forest 把它當成異常；但球掉在邊線附近，對手離球門還遠。XGBoost 學到了「落點靠邊線比較安全」，所以給低分。這是單邊轉換要解決的情況：`end_lateral` 的危險方向是「靠中路」，靠邊線的偏離會被壓成 0。
- **FN（Deportivo）是 H3 的典型**：一次普通的向前傳球失誤，之後經過 6 次傳遞才失球。從失誤當下的任何特徵都看不出來，監督式模型也一樣。

**模型學到什麼**（`results/feature_importance.csv`、`results/figures/fig4_feature_contributions.png`）：
- **XGBoost（TreeSHAP，xgboost 內建的 `pred_contribs`，5 個 seed 平均）**：最重要的是 `end_x`（mean |SHAP| ⟨待補⟩，越小越容易失球），遠高於第二名的比分差（⟨待補⟩，落後時比較容易失球）和 `end_lateral`（⟨待補⟩，越靠中路越危險）。
- **Isolation Forest（遮蔽法：把一個特徵換成正常訓練樣本的中位數，看分數掉多少）**：被標記的前 1% 中，貢獻最大的是回傳（0.041）和 `end_x`（0.036），其次是壓迫（0.023）。兩個模型都把「球落在哪裡」放在最前面；差別在 Isolation Forest 很重視壓迫，但壓迫對失球幾乎沒有預測力（§6.3 A3）。
- 選遮蔽法而不是 SHAP 套件：SHAP 對 Isolation Forest 的解釋是「對路徑長度的貢獻」，需要額外安裝 `shap`（會連帶需要 numba，版本和 numpy 2.5 不一定相容）；遮蔽法直接回答「這個特徵如果是正常值，分數會掉多少」，在只有 6 個特徵時也容易驗證。

## 7. 結論與限制

**結論：**
1. **雙邊 Isolation Forest 和單一特徵基線打平。** 用事先定義的危險特徵，顯著優於隨機；但和「看球落點」的單一特徵相比，PR-AUC 差距的 CI 包含 0，前 10% 與 ROC-AUC 則是單一特徵較好。
2. **原因是危險只在單一方向。** 改成單邊尾端分數（只把往危險方向的罕見值算成異常），PR-AUC 顯著提高 70%（0.0102 → 0.0173），前 1% 抓到的次數幾乎翻倍，在驗證集上也一樣，點估計超過單一特徵。這是本題最主要的發現：**one-class 方法有用的前提，不只是異常罕見，而是「罕見的方向」要和「危險的方向」一致**；方向已知時，把它寫進分數函數比換模型重要（Mahalanobis、kNN、GMM 都沒有幫助）。
3. **能預測的部分很少。** 監督式 XGBoost 的 PR-AUC 也只有 0.030。漏掉的致命失誤平均要 5.7 個事件之後才失球，危險主要來自之後的攻防；被標記但沒失球的失誤，讓對手射門的比例是一般失誤的 5.6 倍，是「危險但沒進」。
4. **資料清理會改變基線的結論。** 落點佔位值修正兩次後，單一特徵的前 1% 從 0 次升到 11 次。第二次的錯誤是誤差分析時發現的：基線的前 1% 有六成是補錯的傳中。
5. **normal-only 在這題不是效果來源**：致命失誤只佔 0.29%，混進訓練資料也幾乎沒有影響。

**限制：**
- **落點補值用了之後事件的位置**（§2.3），是唯一一個用到之後資訊的地方；1,938 次退回用起點，會把傳球長度算成 0。
- **單邊方向是人定的**：`DANGER_SIGN` 依足球常識決定，沒有用標籤，但換一個領域就需要重新定義；方向定錯時，單邊會比雙邊差。
- **單邊尾端是在消融中加入的**：主方法（雙邊）在看到測試結果之前就固定了；單邊是依探索與 §6.2 的觀察提出的假設，雖然它在驗證集上也比較好，但沒有在一開始就放進驗證集的選擇範圍。
- **15 秒是事先選的**，沒有比較其他時間窗。
- **「失誤 → 失球」不是因果**：15 秒內失球不代表是這次失誤造成的，中間可能還有其他事件（FN 平均有 5.7 個）。
- **沒有球員位置的追蹤資料**：失誤當下對手有幾個人在附近、守門員在哪裡，這些對結果影響很大，事件資料沒有。
- **對抗失敗沒有納入**：有些丟球權是在對抗中被搶斷，目前只算傳球失誤。

**下一步：**
1. 把單邊與雙邊一起放進驗證集的選擇範圍，正式成為主方法的一部分。
2. 標籤改成「15 秒內被射門」或用 xG 加權，減少「危險但沒進」造成的 FP。
3. 加入追蹤資料或對手陣型，處理需要多次傳遞才失球的 FN。

## 8. 怎麼重跑

```bash
bash setup_env.sh   # 建立虛擬環境 DM_HW2_G14 並安裝 requirements.txt（只要做一次）
bash run_all.sh     # 約 10–20 分鐘（視 CPU 而定），會自動使用 DM_HW2_G14
```

需要 **Python 3.12 以上**（`requirements.txt` 鎖定的 xgboost 3.4、numpy 2.5、scipy 1.18 都要求 3.12+；`setup_env.sh` 會優先用 3.12）。`run_all.sh` 會依序試 `python3`、`python`、`py`，用第一個能用的；也可以自己指定：`PY=/path/to/python bash run_all.sh`。

**Windows**：用 Git Bash 執行 `bash run_all.sh` 即可（`.gitattributes` 讓 `.sh` 保持 LF 換行）。或在命令提示字元依序手動執行：

```bash
set PYTHONUTF8=1
python -u src/build_turnovers.py
python -u src/turnover_experiment.py
python -u src/ablation_analysis.py
```

| 步驟 | 程式 | 產出 |
|---|---|---|
| 1 | `src/build_turnovers.py` | 讀原始事件、找出傳球失誤、修正落點、算特徵和標籤 → `data/processed/turnovers.csv` |
| 2 | `src/turnover_experiment.py` | 探索、三層方法、顯著性 → `results/`（含每筆測試失誤的分數 `test_scores.csv`） |
| 3 | `src/ablation_analysis.py` | 消融、誤差分析、圖 → `results/`、`results/figures/`；沿用步驟 2 的切分、超參數與分數 |

`src/wyscout_data.py` 是和犯規題目共用的讀取程式（同一個檔案的複本）。

**需要的原始檔**：見 `data/raw/README.md`。把 `events.zip`、`matches.zip`、`players.json`、`teams.json`、`competitions.json`、`coaches.json`、`referees.json` 放進 `data/raw/`。zip 不用先解壓縮；`data/processed/` 和 `results/` 會自動建立。
